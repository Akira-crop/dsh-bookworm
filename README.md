# 书蠹 · Bookworm

微信读书的沉浸式阅读器，装在 DeepSeek Harness 里。

划词就能和 AI 多轮对话。书里的划线、笔记和阅读时长都留在本地。

---

## 它解决什么

微信读书的书架上躺着几百本书，但你真正记得的内容很少。三个具体的问题：

**读完了没留下东西。** 划过的线散在微信读书里，想找「那句关于习惯的话在哪本书」时，只能一本本翻。

**看不懂的地方没人问。** 遇到一段绕的论证，你需要的是「这段在反驳什么」，而不是退出去开一个对话框，再把原文复制进去。

**AI 看不见你的书。** 大多数阅读器把 AI 做成划词挂件，一次一问、答完即忘。你在 Harness 对话框里问「我书架上有哪些书没读完」，它答不了。

书蠹针对这三点做：划线笔记进本地可搜、阅读页常驻对话栏、把书架直接暴露成 Agent 工具。

## 功能

### 书架

- 微信读书扫码登录，一键同步整个书架
- **云端进度直接可见**：同步时读出微信读书的百分比、读到第几章、累计时长
- 「继续阅读」优先接你上次在书蠹里读的书；如果一本都没打开过，就接微信读书进度最深的那本
- 搜索框同时搜书名和**正文**，命中处显示前后文
- 按在读/读完筛选，按最近阅读/加入时间/书名排序

### 阅读

- 四种纸张：跟随宿主 / 纸白 / 米黄 / 夜墨。「跟随宿主」会随 Harness 的明暗模式自动切换
- 衬线或黑体，字号 14–34，行距 1.3–2.6，每行 20–60 字
- 滚动或分页，两端对齐可选
- 结构保留：标题、引文、列表、分隔线、插图分别渲染，不是一律当段落
- 目录抽屉、笔记抽屉、划线抽屉
- 键盘：`←`/`k` 上一页、`→`/`j`/空格 下一页、`t` 目录、`n` 笔记、`Esc` 逐层退出
- 自动记录进度，每 5 秒上报一次；只在真的读进去了才写，切到别的标签页或窗口失焦时不计时
- **阅读时长和进度会写回微信读书**（默认开启，设置里可关）。云端比你更靠后时只补时长、不动位置，**不会用 0 覆盖你在微信读书的进度**

### 划词与 AI 对话

选中任意一段，工具条弹出：**解释 / 补充背景 / 记笔记 / 复制**（解释和补充的先后次序可在设置里改）。

右侧会展开一条常驻对话栏，不遮挡正文：

- 顶部是范围切换：**这段话 / 这一章 / 整本书**
  - 「这段话」带上你划中的原文和它前后各 6 段
  - 「这一章」把整章正文（最多 1.2 万字）交给模型，问「这章在讲什么」才有意义
  - 「整本书」带上全书目录和你在这本书里的笔记
- AI 的回答逐字出现，**底部输入框可以连续追问**，最多保留 24 轮
- 等多的时候会显示秒数计时器，并且把模型的思考过程流式显示出来——推理模型常要先想一分钟以上，干等着会以为卡死了
- **对话栏顶部永远写着这一句是哪个模型在答**，点开就能换：清单来自你 Harness 里已配置的全部提供商和模型，按提供商分组，当前在用的打点标记
  - 换模型不会丢对话历史，接着问就行（旧轮次的复播状态会被剥掉，只保留文字）
  - 选定后记在你的设置里，关掉阅读页再打开还是它；不选就一直跟随 Harness 的默认模型
  - 想快就换非推理模型：实测同一个问题，推理模型首字 82 秒，非推理模型 1.3 秒出全文
- 生成中随时可以停
- **整段对话自动存成一条笔记**（不会每问一句堆一条），可以在笔记页继续编辑
- 对话栏右上角能「在大页面里继续这段对话」，跳到「对话」页
- 切换范围或换书会自动重置会话（旧会话是上一本书/上一个范围的上下文）

### 对话页

侧栏导航的「对话」是独立的大页面版本：选一本书、问它，或者不指定书随便聊。
从阅读页跳过来会带着当前这本书。

### 笔记

- 按书分组，显示章名和时间
- **正文和标签都能改**——AI 的回答存成笔记后也能继续编辑
- 支持标签云，可按标签筛选、按关键词搜索
- **跨书搜内容**：「那句话在哪本书里」可以直接问
- 导出 Markdown：全书或整架

### 微信读书云端数据

- **全部划线按章分组**，可跳回正文对应章节
- **想法**，与你划过的那句原文一起显示
- 170 本有笔记的书，按笔记条数排出「哪本被读得最透」
- 云端统计：本周/本月/今年/总计的阅读时长、听书时长、阅读天数、日均；偏好分类与时段；趋势柱图；勋章墙
- 这些数据只读不写：看得到、改不了。唯一会写回云端的是阅读时长与进度（见「阅读」一节）

### 统计

- 今日 / 最近七天 / 累计 / 连续天数
- 今日目标可以拖滑杆改（5 分钟到 4 小时），不再是写死的 30 分钟
- 七天柱状图
- **按书时长排行**——能看到这本书你到底读了多少
- 单独的「微信读书累计」卡片，显示云端的真实总时长

### 给 Agent 的工具

装上之后，在 Harness 对话框里可以直接问：

| 你说 | 它调用 |
|---|---|
| 「我书架上有哪些书还没读完？」 | `bookworm_shelf` |
| 「帮我在所有书里找提到『财政』的地方」 | `bookworm_search` |
| 「《置身事内》第三章讲了什么？」 | `bookworm_chapter` |
| 「我在这本书里划过哪些线？」 | `bookworm_highlights` |
| 「把我的笔记列出来，按标签分类」 | `bookworm_notes` |
| 「我好像在哪本书里划过一句关于『习惯』的话，找出来」 | `bookworm_search_notes` |
| 「我一共有多少条笔记？」 | `bookworm_notes_overview` |

`bookworm_search_notes` 是跨所有有笔记的书搜云端划线与想法，不是只搜一本。
`bookId` 参数可以直接传书名，工具会自己解析。

## 安装

```bash
# 在 Harness 里，指向这个目录的绝对路径
plugin_manager install_bundle --target <此目录的绝对路径>
```

或者把这个包写进 profile 的 `bundles` 列表，再用 `plugin_manager action:set_bundle` 启用。

要求 Node 22 以上。

## 登录微信读书

1. 打开侧栏的「书蠹」
2. 进「设置」→ 微信读书 → **扫码登录**
3. 二维码用微信扫，手机上确认
4. 登录后自动同步书架

微信读书的登录大约一个月会过期，过期后重新扫码即可。也可以「粘贴 Cookie」手动更新。

**两条凭证分管不同能力**，设置页会分别标注状态：

| 凭证 | 管什么 | 断了会怎样 |
|---|---|---|
| Cookie / 扫码 | 正文、目录、进度、书架同步 | 未缓存的书读不到正文 |
| 官方 API Key（`wrk-` 开头） | 划线、想法、云端统计、跨书搜索 | 云端数据读不到，本地笔记不受影响 |

只有 Cookie 也能正常阅读；只有 API Key 也能看云端划线。两者都配最完整。

**登录能不能长期有效，取决于有没有拿到刷新令牌 `wr_rt`。** 微信读书只在访问站点页面时下发它，JSON 接口不给，
所以书蠹登录后会专门去站点走一趟把它收下来。设置页会告诉你这次拿到没有：
拿到了，过期会自动续期，不用反复扫码；没拿到，大约一天后失效，重扫一次即可长期有效。

早期版本有一个 bug：Cookie 合并会把 Set-Cookie 里的空值照抄进 jar，一次失败请求就能把好的刷新令牌擦掉，
于是每次扫码都只能撑一天。现在空值会被跳过，已经失效的那次重扫一次就好。

## 数据与隐私

全部在 `~/.dsh/bookworm/`（老版本装在 `~/.dsh/wenshu/` 时继续用老目录，不用搬家）：

| 文件 | 内容 |
|---|---|
| `state.json` | 设置、书目、登录凭据、统计数据 |
| `books/<id>.json` | 每本书的目录与已缓存的正文 |
| `notes.json` | 笔记与标签 |
| `cloud-notes/` | 云端划线的本地索引（6 小时后过期重取） |

没有遥测，没有外部上报。删掉这个目录就彻底清理干净。

可以用环境变量 `BOOKWORM_HOME` 换位置。

### 什么会发出去

书蠹不设自己的服务器。你的数据只会去两个地方，都是你主动触发：

1. **微信读书**（`weread.qq.com`）——登录、拉书架、拉目录与正文、拉划线想法。走的是你自己的账号。
2. **你 Harness 里配置的模型提供商**——只有在你提问时，书蠹把「这本书的书名、目录、当前章节、你选中的原文、你的问题」拼进 prompt 发出去。缓存了全文不会自动上传，只有提问范围覆盖到的部分才会。

除此之外没有别的网络请求。

### 什么不会被发出去

- 仓库里没有任何凭据。Cookie 和 API Key 只存本机
- 仓库里没有截图、没有真实书名、没有账号
- 不收集使用统计
- 书的正文、划线原文、笔记内容都不会发给模型提供商以外的任何地方

> 如果你要 fork 这个仓库：不要把 `~/.dsh/bookworm/` 里的任何文件复制进仓库，
> 也不要提交截图——截图里通常有你的真实书架、账号尾号和书的正文。

## 边界

说清楚做不到什么：

- **只支持微信读书**。本地文件、GitHub 书库、PDF、EPUB 都不支持。
- **划线只读**。能看微信读书里的划线，但在书蠹里新加的笔记不会同步回微信读书。
- **正文按章拉取**。第一次打开某章需要联网，之后缓存在本地。整本预下载还没做。
- **正文解析是正则级的**。微信读书返回的是 XHTML 分片，书蠹能认出标题、引文、列表、分隔线、插图，但复杂的表格和脚注会退化成普通段落。
- **等你看到第一个字可能要一分钟**。这是模型本身在思考，不是书蠹卡住。界面上有秒数计时与思考过程可视化；想更快请在 Harness 里换一个不那么爱思考的模型。

## 开发

没有构建步骤。`client.js` 是浏览器端 bundle，直接写 React（用 `h()` 而不走 JSX 编译）。

```bash
node --check client.js
node --check index.js
node --check lib/http-route.js
```

结构：

```
index.js               Host 入口：HTTP 路由 + Agent 工具注册
client.js              全部 UI（React，无 JSX 构建步骤）
cordis.patch.yml       Bundle patch
lib/
  api.js               service 层：所有业务方法
  http-route.js        Request → service 方法的路由表，含 SSE
  http.js              ProviderError 等错误类型
  tools.js             7 个 Host Tool
  ai.js                上下文窗口 + 多轮 + 流式（含 reasoning 转发）
  store.js             本地存储，字段名统一、按书时长
  notes.js             笔记与标签
  cloud-notes.js       云端划线/想法的跨书搜索索引
  gateway.js           微信读书官方 Skills 网关客户端
  providers/weread.js  微信读书 provider
  vendor/weread/       微信读书底层：crypto / qr-login / reader / web
```

设计约定：

- **Host 与 UI 走同一份 `service`**。界面上能做的事，Agent 那边一定能做。
- **界面走同源 fetch**（`/bookworm/api/*`），不用 `host.call`——静态 client 插件拿不到 `host` 符号。
- **CSS 类名统一 `ws-` 前缀、变量统一 `--ws-`**，颜色走宿主的 `--dsw-alias-*`，深浅色自动跟随。
